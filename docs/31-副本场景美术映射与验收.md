# 副本场景美术映射与验收

> 目的：把 13 个 NPC 小副本从“共用街区图或 CSS 占位”逐步推进为有明确地点识别度的独立游戏场景。本文记录当前实现事实和美术缺口，不代表未完成的场景已制作。

## 统一场景方向

- 采用像素风的 2.5D 场景表达：纵深来自等距/斜俯视环境、前后景遮挡和人物落点，不把窄屏背景横向拉伸成宽图。
- 街区仍是一张可探索的大场景；进入小副本后切换到对应的独立地点。副本的操作、反馈和结算留在场景里，不用一张通用对话面板代替玩法。
- 每个场景至少需要一个能一眼识别职业/地点的环境锚点。背景与 NPC 立绘分开制作；街区和 13 个对应副本现均使用各自的独立静态人物素材，仍是单帧样板，不算动画美术定稿。
- 场景图不烘焙标题、按钮或对话文字。按手机竖屏构图，重要交互区域预留干净空间；场景容器使用等比裁切，不拉伸图片。

## 郑师傅场景样板验收

- 资源：`public/art/zheng-repair-workshop-v1.png`。
- 接入：维修副本背景使用独立图片，前景的安全提示、工单和操作仍由 DOM 渲染；不把 UI 烘焙进美术资源。
- 构图：以 `object-fit: cover` 适配窄屏，不变形；暗部覆盖层帮助前景文字阅读。
- 功能边界：没有改维修工单、精力、收入、Reducer 或存档逻辑。
- 待核验：不同手机高度下，标题牌和工单卡片是否遮住关键工具/电驴；确认后再把这套接入方式推广到其他副本。

## 王老板工厂场景样板验收

- 资源：`public/art/factory-inspection-floor-v1.png`。

- 构图：竖屏工厂纵深图使用等比裁切，中央保留传送带与质检台；底部压暗以承托工单卡片。
- 功能边界：没有改工厂情境、选项、奖励、精力、Reducer 或存档逻辑。
- 待核验：窄屏和矮视口下标题、工单卡片是否遮挡质检台关键物件；资产加载失败时 CSS 底色可作为退化背景。

## 推进顺序

1. 13 个 NPC 副本现在都有各自的地点背景；接下来在浏览器与手机窄屏逐一验收构图、遮挡、操作可达性和回街区路径。
2. 副本预览入口：打开 `?artPreview=1&activity=list` 可查看全部 13 个副本；也可用 `?artPreview=1&activity=CHEN_DOSSIER` 直接打开指定副本。预览使用固定初始状态、不读取或写入存档，操作仍走真实 reducer。
3. 13 位 NPC 均已接入独立透明角色图样板，并完成 480×720 游戏画布检查；街区热点与阿浩长对话也已完成 320×568、390×844 浏览器视口仿真检查。真实手机触控、弱网加载和各副本页面窄屏仍需单独验收。
