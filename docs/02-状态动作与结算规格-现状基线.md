## 3. GameState 字段表（全部 18 个字段）

金额单位为游戏内元；股份单位为股。number 类型本身不提供业务取值范围。

| 字段 | 类型 | 现状与主要写入者 |
|---|---|---|
| `day` | number | 初始 1；NIGHT 的 ADVANCE_PHASE 加 1 |
| `phase` | GamePhase | PRE_MARKET / DAYTIME / TRADING / NIGHT；初始 PRE_MARKET |
| `cash` | number | 初始 3200；打工、借贷、成交改变 |
| `debt` | number | 初始 18000；借款增加；暂无还款/利息 Action |
| `stocks` | Record<string, StockState> | 初始仅 dragon；Tick 和成交更新 |
| `selectedStockId` | string | 初始 dragon；SELECT_STOCK 验证存在后更改 |
| `inputShares` | number | 初始 100；输入原样写入；下单及跨日复位 100 |
| `lastOrderFeedback` | OrderFeedback 或 null | 初始 null；下单覆盖；清除和跨日置 null |
| `orderSequence` | number | 初始 0；每次 PLACE_ORDER 都加 1，跨日不清零 |
| `npcMessage` | string | 初始消息；跨日替换为固定消息，无 NPC 事件系统 |
| `energy` | number | 初始 100；选角回满，WORK 减 25（最低 0），跨日回满 |
| `workedToday` | boolean | 初始 false；有效 WORK 设 true；跨日 false |
| `dayStartEquity` | number | 初始净资产四舍五入到分；跨日记录跨日前净资产 |
| `dailyWorkIncome` | number | 初始 0；WORK 累加；跨日归零 |
| `dailyFees` | number | 初始 0；累加成交反馈 fee，到分；跨日归零 |
| `gender` | MALE / FEMALE / null | 初始 null，入口据此显示选角；SELECT_CHARACTER 设置 |
| `energyMax` | number | 初始 100；选 MALE 设 120，FEMALE 设 100 |
| `leechLevel` | number | 初始 100；每次有效借贷减 10，跨日不恢复 |

### 子结构与不在状态中的数据

- `StockState`：id/name；price/open/high/low/volume；priceHistory；bids/asks；recentTrades；scriptPhase/phaseProgress；可选 holding（shares、avgCost）。初始 holding 为 800 股、均价 11.85，此为临时原型值。
- `OrderBookLevel` 为 price/volume；`TradeRecord` 为 id/price/shares/side/isPlayer。内部 scriptPhase 为 ACCUMULATE/PUMP/DISTRIBUTE/DUMP，不是玩家可见规则说明。
- `OrderFeedback`：id/stockName/side/requestedShares/filledShares/requestedPrice/filledPrice/slippagePct/fee/latencyMs/result/可选 rejectReason/cashAfter。result 为 FILLED/PARTIAL/REJECTED；slippagePct 是比例数，0.001 对应 0.1%。
- 融资开关、输入错误、反馈卡实例、定时器、当前 NPC 对话为 UI 局部状态，不进 GameState。无 dayTick、章节、重组、心态/体面/流量字段。

## 4. Action 合同（当前实现）

“无阶段限制”表示 reducer 不校验，不代表任何阶段都应允许玩家操作。正常入口见第 5 节。

| Action 与载荷 | core 接受条件 | 结果及不改变的关键项 |
|---|---|---|
| `ADVANCE_TICK` | 无阶段限制 | 所有股票 tickStock；不改 day、phase、现金、债务 |
| `ADVANCE_PHASE` | 按当前四阶段枚举 | 顺序推进；仅 NIGHT 分支跨日并做第 5 节重置 |
| `SELECT_CHARACTER { gender }` | 无一次性/阶段校验 | 设置 gender/energyMax/energy，phase 回早盘；不清空已有资产和 day |
| `CHANGE_PHASE { phase }` | 无前后阶段校验 | 只替换 phase；跳入早盘也不会执行跨日重置 |
| `SELECT_STOCK { stockId }` | stockId 存在 | 替换选择；不存在时返回原 state |
| `SET_INPUT_SHARES { shares }` | 无运行时校验 | 原样写入；不保证正整数或整手 |
| `PLACE_ORDER { side, shares, leverage? }` | 无阶段限制；引擎检查股票、正整数数量、资金/持仓 | 默认 leverage=1；引擎处理成交后，输入复位、覆盖反馈、序号+1、累计 fee；拒单也执行这些外层更新 |
| `WORK` | DAYTIME 且未打工且 energy>0 | FEMALE 收入 180，其余 150；现金/当日收入累加，体力减 25 到最低 0，workedToday=true；条件不符返回原 state |
| `BORROW_FROM_NPC` | DAYTIME 且 leechLevel≥10 | 现金、债务各+1000，leechLevel−10；没有 NPC 身份参数；不满足条件返回原 state |
| `CLEAR_ORDER_FEEDBACK` | 当前反馈非 null | 反馈置 null；本来为 null 时返回原 state |

### 成交的现状边界

- 委托不要求 100 股整手；UI 快捷数量按 100 股取整，不能据此推导 core 有整手校验。
- 买入先按全部委托的盘口金额及 0.0015 手续费率检查资金；卖出先按全部委托检查持仓，之后才决定是否部分成交。
- 部分成交概率代码值为 0.15，成交股数 floor(shares×0.6)，须大于 0；其余视为全成。这些不是批准后的平衡参数。
- 买入现金减撮合金额和费用，均价把费用计入成本并保留 4 位；卖出现金加撮合金额减费用，卖完删除 holding。
- 成交会改变最新价、日内高低、量、历史、盘口和流水；现金按 notional 计算，filledPrice 为均价到分，不能假设二者相乘恒等。
- latencyMs 是反馈数据（普通 300–400ms，异常 1500–2200ms），core 同步成交；没有待成交队列、撤单或真实延时执行。
- leverage>1 只影响合成盘口冲击，不增加可用资金或债务；不能把现有 UI 融资开关视为正式融资机制。跟随 NPC 参数存在于引擎，reducer 没有传入它。
- 随机数按当前状态和委托信息确定种子；相同输入可重现。拒单也消耗 orderSequence，后续委托的种子会变化。

## 5. 阶段、计时和跨日

| 正常 UI 入口 | Action | 结果 |
|---|---|---|
| 无 gender 时选角并进入盘城 | SELECT_CHARACTER | PRE_MARKET；选角不是第五个 GamePhase |
| 早盘“进入白天” | ADVANCE_PHASE | DAYTIME |
| 白天交易所入口 | ADVANCE_PHASE | TRADING |
| 交易“今天不操作，去结算” | ADVANCE_PHASE | NIGHT，先停当前 ticker、dismiss 反馈卡、destroy 图表 |
| 结算“进入第 N+1 天” | ADVANCE_PHASE | day+1、PRE_MARKET，并执行下列重置 |

跨日重置：inputShares=100、lastOrderFeedback=null、固定 npcMessage、energy=energyMax、workedToday=false、dayStartEquity=跨日前净资产到分、dailyWorkIncome=0、dailyFees=0。

跨日保留：cash/debt、全部 stocks（含 open/high/low/volume/history/剧本进度/持仓）、selectedStockId、orderSequence、gender/energyMax、leechLevel。当前没有“新交易日重置开盘价”等规则。

- UI 交易屏挂载时启动 3000ms interval；普通提前结算路径停止它。core 的 ADVANCE_TICK 本身无 TRADING 限制。
- 不存在 60 Tick 日计数或自动收盘；历史数组上限 120 不能当作每日计数。
- 每只股票内部剧本每 10 次 Tick 轮换，四阶段循环。成交也追加历史，因此历史长度更不能代表 Tick 数。
- 页面刷新从存档恢复状态，重新挂载交易页后创建定时器；没有持久化时间戳补 Tick、后台暂停/恢复规则或离线补算。
- `CHANGE_PHASE` 不是正常 UI 推进路径。绕开提前结算入口时，不能据当前实现保证统一销毁交易资源；这是后续生命周期验收项。

## 6. 结算账务与展示

定义持仓市值 V=Σ(holding.shares×stock.price)，净资产 E=cash+V−debt，开盘基线 B=dayStartEquity。

| 项目 | 当前计算 |
|---|---|
| Night 今日净变动 N | round2(E−B) |
| 打工收入 W | dailyWorkIncome |
| 手续费展示 F | −dailyFees |
| 交易盈亏 T | round2(N−W+dailyFees) |
| 利息、房租/生活 | 都为 0；没有额外扣款 |
| 明细勾稽 | T+W+F=N（到分精度；利息/生活项为零） |
| 负债警示 | debt>cash+V 时展示“请留意强平线”；没有实际强平动作 |

- 进入/显示 Night 只生成 VM，没有记账 Action；再次查看不会再次扣费用。成交费已在成交时扣除，结算只展示。
- “手续费/滑点”行实际上只有手续费；滑点影响现金与持仓估值，包含在净变动和交易盈亏中，未单列费用。
- 未出售持仓按最新价计入净资产，因此 tradingPnl 不是已实现收益；借款同时增加现金和债务，净资产不因此增加。
- mental=42、dignity=55、fame=38 和 NPC 评价继承 mock，不是状态结算结果。警示列表则由真实债务与资产比较替换。
- 主入口的氛围用未 round2 的 E−B 判断正/负/零；Night 的 N 到分。极小浮点差可能出现氛围与显示零值不一致，此处仅记录待验证差异。
- 第 30 天没有特别分支，照常进入第 31 天；这不等于已实现“保留存档的债务重组”。

## 7. 存档关联（本次不改兼容性）

- localForage 数据库名 leek-rise、store 为 game_saves、键 current；封套 {version:1,savedAt,state}。保存整个 GameState；UI 局部状态不保存。
- 主入口启动时先尝试读取；有效存档替换初始 state。返回新 state 引用的 dispatch 排队保存，未变化的原引用不触发保存。
- Zod 校验结构和枚举，数值没有业务上下界、整数、股票选择存在性或账务一致性约束；通过结构校验不代表满足玩法不变量。
- 无存档返回 null；读取失败/格式或版本不支持时显示提示并使用初始状态。随后开始新进度可能替换旧存档；无备份、迁移或损坏存档恢复流程。
- 新增章节、Tick/重组字段之前需单独设计 schema 版本与迁移；本阶段没有变更任何存档字段。
