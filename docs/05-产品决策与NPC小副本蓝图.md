# 《韭菜翻身》产品决策与 NPC 小副本蓝图
> 版本：2026-10-30。本文记录用户已接受的核心体验方向，并把它变成可执行的玩法与开发规则。与旧工作稿、旧 NPC 矩阵或现有原型冲突时，优先遵从本文；未标“已确认”的内容仍是设计提案。
## 1. 已确认的产品方向
- 玩家进入盘城是为了赚钱、改善处境并争取翻身；不能把“玩家注定亏损”当作底层规则。 - 交易、打工、NPC 任务等路径都可以产生可理解的收益；玩家不保证每局赚钱，但必须能靠判断、选择和熟练度提高结果。 - 亏损应来自玩家能理解的风险、线索、机会成本和选择，而不是隐藏的必败概率或每笔交易都暗扣的隐性惩罚。 - 盘城、债务和 NPC 保持讽刺与压迫感；压力推动玩家做决定，但必须留有恢复、换路和继续游玩的空间。 - 每个打工入口与 NPC 任务都可以发展成独立小副本。副本要有自己的场景、主要操作、过程、结果和回到街区的路径，不能用一句对话直接发钱代替玩法。 - 多副本是产品差异点：不同偏好的玩家可以选择不同的赚钱过程；最终目标仍是改善经济处境。 - 第 30 天未达到目标时进入债务重组/危机阶段，保留当前存档继续玩，不直接 Game Over。 - 这些决定不等于已确认交易 Tick 时长、费率、收入、费用、概率或副本数值；相关数值需经模拟与试玩调整。
### 整体体验原则：一座街区，多种赚钱游戏
- 白天主场景是完整、连续的大背景街区；NPC 和地点分布在场景里的具体位置，头顶有可触发提示。点击后进入对应对话，再选择继续聊天或进入独立副本。街区不是四宫格菜单，也不要求先实现自由移动或战斗系统。 - NPC 副本是本作的主要差异点：每条支线应有自己的玩法主循环和场景表达，玩家可以因为喜欢跑单、经营、推理、谈判或交易而留下；不同玩法最终都回到同一套现金、债务、精力、关系和日历状态。 - 赚钱不是单一的“领奖”动作。直接收入副本负责提供可操作的现金来源；调查、训练和谈判副本可以提供情报、成本改善或新机会。结算必须让玩家看懂它怎样帮助经济处境，不能用虚拟分数伪装成现金收入。 - 这是已经确认的产品方向，不代表所有 NPC、副本、台词和美术都已完成。先建立完整街区入口和清晰的未开放状态，再按可玩闭环逐个交付副本，避免堆出大量只有入口、没有过程的内容。
## 2. 玩家收益与压力规则
### 2.1 盈利感
1. 玩家要能在前几个循环内体验到靠判断或行动拿到的正向结果，并看懂结果是如何产生的。
2. 赚钱过程本身要有可操作性：收集信息、分配资源、选择路线/对象、执行操作、承担结果。
3. 角色成长应增加可选方法、信息质量或操作能力，而不只是让数字变大。
4. 允许出现亏损、欺骗、失误和极端事件；事件必须有线索或清楚的风险提示，不能把“暗中改赔率”作为常态难度。
5. 交易费用与副本成本显示在结算或选项中。可以让 NPC 隐瞒事实，但不能让游戏系统隐瞒结算规则。
### 2.2 长线压力
- 债务、生活成本、精力、名声与人际关系可以构成不同压力轴；具体字段和数值尚未定案。 - 不交易可以是一条玩法路线，但它需要面对时间、收入上限或其他机会成本，不能被规则强制判死。 - 系统提高难度时，优先增加新的选择、环境变化、NPC 反制和目标，不靠无限叠加固定费用把所有策略压成亏损。 - 玩家可以因错误选择进入危机，但应看到债务重组、协商、支线赚钱或其他补救机会。
- 第一章、进阶章和长期模式的长度、解锁条件、日内时长及失败规则仍待策划与数值模拟，不由旧稿中的候选数字自动决定。
## 3. NPC 小副本的产品契约
每个副本都按自己的核心玩法设计，共用生命周期，不共用同一套谜题或按钮换皮。
| 环节 | 规则 |
|---|---|
| 入口 | 从 NPC 或工作地点进入；显示玩法主题、前置条件、会消耗的资源和可见风险 |
| 开始 | 建立可保存的活动状态；进入独立场景；不在入口处直接发放完成奖励 |
| 过程 | 至少有一个反复可操作的核心行为，包含可读线索、选择或技巧空间 |
| 反馈 | 操作后展示原因与变化；避免用纯随机决定全部输赢 |
| 结算 | 明示收入、成本、精力与其他状态变化；奖励由 core 规则结算 |
| 退出 | 允许按规则退出或完成；回到进入副本前的 Hub；保留合理的中断/恢复状态 |
| 扩展 | NPC 对话、场景、美术、玩法规则和经济结果分离；增加新副本不复制整套主路由 |
### 技术边界
- Core 只保存活动状态、接受动作并结算结果；不依赖 DOM、Phaser 或 UI 文案。
- UI 屏幕只采集玩家输入、显示当前副本状态和反馈，不自行决定金钱结果。
- 每种玩法使用严格的联合类型或独立纯逻辑系统；不用 any，不用无类型大字典传业务状态。
- 存档必须包含活动状态，并为现有存档提供版本迁移；进入副本后刷新不能凭空丢失或重复领奖。
- 共用层只负责开始、继续、完成、退出和回 Hub；地图、解谜、谈判、经营、路线规划等玩法由不同副本模块实现。
- 入口尚未实现时，显示明确的“尚未开放”对话，不扣费、不改变状态、不假装已完成副本。

## 5. 首个垂直切片：王总的外卖跑单
首个可玩切片已打通街区入口、独立路线选择、core 收入/精力结算、结算回执、回 Hub 与存档状态。它验证的是活动生命周期原型，不代表其他 NPC 副本已经实现。
- 场景从街区的外卖驿站进入；王总交代当天临时单。
- 核心玩法围绕订单与路线/时限/精力分配，不做纯文字选择题，也不在点击入口时直接发固定工资。
- 每次选择显示已知报酬、资源成本和风险；过程结果由玩家决定，意外只改变局部，不覆盖全部操作。
- 结束后展示完成订单、收入、精力消耗和失误原因，玩家可以回 Hub 再进入交易或其他副本。
- 当前原型为 3 个路线情境；路线报酬分别为 ¥35/¥62、¥58/¥28、¥64/¥45，精力成本分别为 10/12、12/10、22/10。全部为临时参数，最佳路线总收入 ¥184，不是正式经济平衡结论。
- 当前界面/收入/精力/存档字段均为首版原型；后续可基于试玩调整，不把这些临时参数升级为正式经济规则。
## 5.4 王老板的工厂质检班
- 从街区小工厂进入独立班次场景，连续处理三个质检工位；每件货都给出可核对的工单与实物线索，玩家选择返工复检或直接放行。
- 完成班次获得 ¥60 基础工资，每个正确检查加 ¥20；判断错误仅失去该项质量奖，不倒扣现金。具体工资是原型假设。
- 放行消耗 5 点精力，返工消耗 9 点；Core 会为后续工位保留最低精力，开班后可以完成整班。正确路线每天消耗 19–23 点精力。
- 与外卖跑单共用 `workedToday`，每天只能选择一种工作；收入进入 `dailyWorkIncome` 和 Night 打工账目。每次选择由 Core 判定，活动过程与结算单存入 v10，兼容 v1–v9 存档。
- 30 天、全做正确质检、0 个交易 Tick 的 reducer 模拟中，工厂班每天收入 ¥120，扣周期成本后净资产仍上升；这是理想路线的原型证据，不代表玩家结果或正式经济平衡。
## 5.5 K线菩萨的三张图练习
- 从培训班 NPC 进入独立读图场景，依次判断抬高低点、突破量能不足和窄幅震荡；每题有三种可读选择，错误会显示复习记录，不把结果交给随机数。
- 每题消耗 3 点精力，至少 9 点才能开始；每日一次。中途离开保留已耗精力并锁住当天重进，避免反复刷答案。
- 3 题答对至少 2 题时，根据所选股票最近最多 8 个价格点生成一条低置信度的历史走势提示；不发现金、不预测下一步、不自动下单。趋势提示明确说明历史图形不保证延续。
- 活动状态进入 v11 存档，v10 及更早存档安全迁移；活动结果与选择可恢复，Core 负责答案校验、精力扣除和提示结算。
- 当前题目、精力成本和阈值均为可玩的原型规则；P2-v21已补齐存储替身下的27路线、逐步恢复、退出与账本验收（docs/21），尚未做浏览器持久化/真实视口试玩或正式经济平衡；练习是否足够有趣、提示是否值得精力，仍需玩家体验后调整。
## 5.6 苏姐的街角咖啡短班
- 进入街角咖啡独立班次，轮流服务赶单骑手、熟客和带娃家长；听取各自需求，从三种饮品中选择服务方案。
- 完成三杯必得 ¥72 底薪，每次匹配需求加 ¥16 小费，班次收入范围 ¥72–¥120；判断失误只失去该杯小费，不扣本金。
- 每杯消耗 5 点精力，开班至少需要 15 点；完成后和跑单、工厂质检共用每日工作名额。中途离开保留已耗精力、不发工资，可在精力足够时重进或改做其他工作。
- 班次收入进入 `dailyWorkIncome` 与夜间打工账目；活动过程/结算可存档恢复，v12 接受 v1–v11 存档，并保留 v11 读图活动。
- 经济实验加入 CAFE、CAFE_STREAM 与 CAFE_CASH（首日清仓后只做咖啡班）路线，按现有统一结算规则比较多日收入、精力和还款结果。
- 工资、小费、顾客数量和精力是可调整原型值；仍需真实试玩确认选择是否有趣、提示是否清晰，再结合多日模拟调整，不能当作已定稿平衡。
## 5.1 第二个切片：龙哥的群聊鉴伪
- 入口从盘城街区的龙哥烧烤摊进入，独立显示群聊留档、成交回放和公告核对三个阶段。
- 每阶段各有一个深入核查和一个表面观察选项；玩家最后判断“借利好出货 / 真实利好 / 证据不足”。只有多个可靠核查项互相印证时才给较高可信度；判断证据不足也是合理选择，不会扣现金或精力。
- 案例在副本开始时读取所选股票的剧本阶段：积累期保持方向不明，拉升期核对可验证利好，派发/下跌期核对旧消息与卖压。剧本和盘口由 core 共用，副本不另造一条市场走势。
- 情报保存在 `GameState.marketIntel`，限定当天与对应股票；回到交易屏后显示在 NewsHint。它提供方向线索，不自动替玩家下单、不改价格或手续费。
- 每天只可调查一次。副本中途可主动退出并放弃当日情报；活动进度进入 v3 后续存档结构，可在刷新后继续。
- 当前完成边界：入口 → 3 次取证选择 → 判断 → 情报回执 → 回 Hub → 交易屏展示。案例内容、剧本阶段标签和可信度阈值是原型决策，需由玩家试玩确认，不视为最终策划案。
## 5.2 第三个切片：小镰刀的直播运营
- 从小镰刀 NPC 或旧城直播间进入，单独进入直播场景，分为选题、弹幕互动、成交收尾三段。
- 每段消耗 5 点精力；开播即锁定当天次数，中途退出保留已耗精力且不发奖励，完成后一次性结算现金和粉丝变化。
- 每个选项明确展示热度、信任、成交意向与精力变化。收入原型公式为「成交意向 × ¥10 + 每 10 点热度 ¥5」，女性角色再获得 20% 直播成交加成；口碑变化反馈为粉丝增减。
- 选择诚实实测、认真答疑和透明成交，短期收入较低但可增长粉丝；夸大承诺、循环催单和虚构稀缺带来更高短期成交，同时损害信任/粉丝。这是确定性选择结果，不用暗骰强迫玩家亏损。
- 每日直播一次；结算写入 `cash`、`dailyStreamIncome` 和 `fame`，由 Night 账本单列副本收入；Core 规则和状态可保存，UI 路由由活动注册表管理。
- 当前全部数值是 P2-e3 原型假设，不代表正式平衡；未纳入生活成本、利息或还款目标，需在试玩与经济模拟后调整。
## 5.3 第四个切片：陈总的公司材料调查
- 从写字楼的陈总 NPC 进入独立资料室，依次核验合同备案、供应商交付和发票回款，再决定继续观察、回避或暂缓行动。
- 每一步可花 6 点精力查原始材料，也可花 1 点快速浏览路演稿、口头说明或预测；快速浏览不增加可信证据。每个阶段和资源成本都在选择前展示。
- 案例读取所选股票当前的剧本阶段：拉升期对应真实合同，派发/下跌期对应夸大订单，积累期对应暂未出现明确催化。原始材料会给出可交叉验证的结果；高可信线索写入当日、该股票的 `MarketIntel`，在交易屏显示陈总来源和核验结果，不改价格、不自动下单、不直接发现金。
- 每天最多调查一次；中途退出保留已消耗精力且不发情报。活动过程存进 v5 存档，并给 v1–v4 存档补默认值。
- 这是调查与取舍原型，不是即时赚钱副本。它的价值在于提供玩家可自行采用的交易信息；案例频率、信号可靠度及能否形成可感知的交易优势，仍需试玩和经济模拟验证。
