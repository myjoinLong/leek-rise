# 外卖副本：真实浏览器持久化恢复验收

## 本轮里程碑 P2-v1（2026-10-30）

产品/系统核对恢复契约，UI 与存档工程执行浏览器验收。不是新增副本，也不修改经济参数。
此前活动生命周期测试使用存储替身；本轮在真实浏览器中操作正式入口、刷新和重开标签页。

## 环境与步骤

- 使用独立源 `http://127.0.0.1:5189/`，Vite 开发模式；不带 `artPreview`，不改写常用端口的游戏存档。
- 使用原生 UI 选择男性角色，进入早盘、街区、外卖驿站及跑单场景。
- 全程调用现有 main → reducer → saveGame/loadSavedGame；没有注入游戏状态或手动修改余额。
- 使用实际 localForage 存储；没有替换驱动。未直接读取底层驱动名称，故不单独断言 IndexedDB 驱动覆盖。
- 依次选择穿小巷、主路连廊、加速冲单；在每个操作前、结果页、返回 Hub 后执行页面刷新。
- 完成后关闭标签页，再新开同源页面，核对自动载入。

## 并发干扰与边界

- 运行开始时已有工厂副本改动，且相关源码仍持续写入。本轮没有修改或接管这些代码。
- 首次刷新期间，正在拆分的 schemas 模块临时抛出 `deliveryRunSchema is not defined`，出现白屏；模块写完后重新刷新，原活动成功恢复。该次白屏记为干扰，不计成功样本。
- 检查点记录中 `entry` 恰处于上述干扰，`hub`/`hubReload` 是无变化差异文本；完整证据使用 `entryReload`、`hubFinalFull` 与 `reopenedTab`。
- 本轮证明已等待持久化后的刷新与标签重开；不证明点击瞬间强制关闭、崩溃、断电、多标签并发写入或存储拒绝后的可靠性。
- 未覆盖全部副本、移动设备、生产构建、完整读屏或浏览器进程重启。没有把单路径收入当作正式平衡。
- 已确认方向仍是独立操作、Core 结算、保存不重复领奖；本轮无新数值假设或产品方向偏离。正式合同、章节目标与危机退出规则仍待决。
