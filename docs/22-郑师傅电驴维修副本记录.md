# 郑师傅电驴维修副本记录

## 玩法目标

提供一条与跑单路线规划、咖啡需求匹配、寄售定价不同的收入玩法：玩家先读故障症状，可决定是否花精力检测，再选择维修部件。玩家的诊断与资源选择决定质量奖，Core 负责验证和结算。

## 已落地规则（原型参数）

- 每次进入维修班处理 3 张工单；工单随日期轮换，共有电池、刹车、控制器三类故障。
- 每张工单完成后发放 ¥18 底薪；修对再发 ¥12 质量奖。修错只损失这张工单的质量奖，不扣现金、不增债。
- 每次维修消耗 5 点精力；检测一个部件消耗 2 点，每张工单的每个部件最多检测一次。Core 会为剩余维修保留最低精力，不能靠检测把班次锁死。
- 开工时占用当天唯一工作名额。已消耗精力不退；已完成工单工资已经到账，未完成工单没有工资。
- 活动过程与检测/维修记录进入 GameState；存档版本升至 v18，v16/v17 活动按旧联合 Schema 读取，旧版本迁移不增加字段。

- 独立浏览器源 `http://127.0.0.1:4176/` 完成男骑手新档→早盘→街区→郑师傅→3 张工单→返回街区→刷新。首单检测并修对，次单故意修错，末单修对：现金 ¥3,200→¥3,278，精力 120→103，债务不变；回 Hub 后刷新，现金/精力和郑师傅“今日已工作”锁均保留。验收使用新 origin，不读取或覆盖用户原有存档。
