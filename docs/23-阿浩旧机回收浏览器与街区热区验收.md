# P2-v23 阿浩旧机回收浏览器与街区热区验收

## 角色与范围

- 角色：产品/系统验收与前端体验。
- 验收对象：阿浩旧机回收副本的真实浏览器操作、正常模式刷新恢复，以及盘城街区触发点在 320×568 下的可点击性。
- 本轮只调整街区热点视觉与两个坐标；不改 Core 交易规则、收益、精力、存档格式或依赖。

## 浏览器流程

在不带 `artPreview=1` 的正常模式下，从选角依次进入早盘、街区和阿浩副本。使用隔离的 `localhost:3000` origin，避免读取或覆盖现有 `127.0.0.1:3000` 预览存档。

1. 第一台手机验机后议价直接转卖：现金 ¥3,200→¥3,412，精力 120→117，净收益 +¥212；刷新后仍在第 2 张回收单，已完成回执、现金和精力均保留。
2. 第二台手机验机后按标价整备转卖：现金 ¥3,412→¥3,532，精力 117→114，累计净收益 +¥332；刷新后仍在第 3 张回收单，前两笔收入没有重复发放。
3. 第三台选择放弃：最终回执列出两笔成交和放弃原因，累计 +¥332；返回街区后阿浩显示“今日已工作”。再刷新仍保留 ¥3,532、114 点精力及工作锁。

## 街区布局核查

- `DaytimeScreen.ts` 将 NPC 入口显示为 52×60px 人物热区，满足最小 44×44px 触摸目标。可用入口使用 `!` 对话提示，完成项使用 `✓`，暂不可用项使用 `·`；姓名标签仅在悬停/键盘聚焦时出现，完整入口状态保留在 `aria-label` 与对话框中。
- 320×568 下 13 个 NPC 热区互不重叠，也不与顶部 HUD、底部提示或交易所门重叠；点击阿浩能打开正确的“阿浩 · 旧机回收铺”对话。480×720 下热区也无互相重叠。
- 为避免右侧 NPC 相邻触发区域碰撞，周经理横向锚点从 x=77% 调至 x=74%，阿浩纵向锚点从 y=27% 调至 y=31%。这只是全景图上的热点位置，不改变入口或底层位置数据。

## 构建与证据边界

- `npm run build`、`npm run lint` 通过；`DaytimeHubEntries.test.ts` 及 `storage.test.ts` 合计 19 项通过；街区预览浏览器错误日志为空；`git diff --check` 无空白错误。
- Vite 仍提示 Phaser 独立 chunk 压缩后约 1.37 MB，构建成功但包体优化待排期。
- `artPreview=1` 会跳过存档加载和写入，因此该模式刷新回选角不代表存档故障；持久化结论来自正常模式的隔离 origin。
- P2-v23 当时未在 320×568 下实玩手机副本本体；后续小视口验收见 docs/24。本轮也未覆盖真实触屏设备、读屏、全部 NPC 入口、长期经济平衡或多日模拟；三台回收货的收益只是可复现原型样本，不是正式经济数值。
