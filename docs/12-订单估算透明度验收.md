# 订单估算透明度验收

> 日期：2026-10-30。记录交易界面订单金额估算修复，不代表交易参数已完成正式平衡。

## 修复内容

- 买入支出与卖出净收入分别按当前盘口估算，避免卖出按钮展示买入成本。
- 两侧估算统一使用 Core 的盘口档位与费用舍入规则；当前费用合计为成交额的 0.15%。
- 输入错误只用于非法股数，不再把“买不起”误报成通用红框；买卖按钮分别按资金与持仓可行性启用。
- 融资暂不可用时禁用控件并明确提示。现有状态没有完整的融资现金、债务、利息和强平账务，不能把杠杆开关展示为真实融资。
- 订单面板说明当前原型的部分成交概率与剩余撤单规则。估算按请求数量和当前可见盘口计算，实际部分成交金额可能不同。

## 验收证据

- 新增订单估算测试覆盖买卖方向、费用舍入、现金变化、资金边界和非法数量。
- `npm run build` 与 `npm run lint` 通过；定向 Vitest：1 个测试文件、3 项通过。
- 浏览器验证：卖出 100 股后现金增加 ¥1,000.50，与 100 × ¥10.02 − ¥1.50 费用相符；输入 500 股时，买入按钮因买入额度不足禁用，卖出仍可用，且没有错误的“资金不足”红框。
- 320×568 窄屏下四行预估内容均未发生水平截断；非法 50 股会提示整手数量规则，恢复 100 股后买卖按钮可用。
- 未验证全量浏览器回归、所有活动副本或正式经济平衡。构建仍有 Vite 大包体积提示。

## 后续决策

- 正式融资前需定义借款额度、利息计提、可用现金口径、担保品与强平规则，并通过同一结算函数驱动预估和实际成交。
- 盘口可见深度不足时的超量委托规则仍需明确；当前估算不承诺超出可见档位后的最终成交价。
