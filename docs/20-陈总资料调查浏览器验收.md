## 实际流程

1. 从第 2 天街区点击陈总，进入“公司材料调查”。开始时现金 ¥3,200、精力 100，标的是龙科科技。入口说明至少需要 3 点精力。
2. 依次选择“调取合同备案原件”“核对供应商交付单”“交叉核对发票台账”，每项显示并扣除 6 点精力，总计 18 点；现金保持 ¥3,200。
3. 第一项取证后刷新页面，恢复到“资料核验 2 / 3”，精力仍为 94，已完成的合同备案选择与反馈仍显示，没有重复扣除。
4. 首轮修复前，三项完成后都回显“没有发现能推动当前交易的新增合同”。选择“证据不够，暂时不行动”，回执显示“稳妥观望”和较高可信的材料结论。回到街区后精力为 82/100、现金 ¥3,200，陈总入口显示“今日已核验”并禁用。
5. 进入交易屏，NewsHint 显示“【陈总】较高可信”及“你选择暂缓入场”的结论。未提交交易；交易屏正常展示盘口、流水与订单面板。
6. 第 2 天正常结算后进入第 3 天，再完成“订单夸大”案例。Core 评分调整前的浏览器回归中，合同编号、供应商排期、发票/回款分别展示不同核验结果；选择“谨慎回避”后，回执保留三条分项。当时各来源结果相同，不能代表本轮新增的混合证据结果。
7. Core 评分调整后再次通过普通入口进入第 3 天副本。真实界面显示合同登记不符、供应商排期相符、发票回款不符；选择谨慎回避后，回执显示“可核验材料之间存在冲突”，汇总为 2 项负面、1 项正面，可信度偏低。现金仍为 ¥3,200，精力 100→82，没有下单；回执不再重复“暂缓入场”。

## 发现与后续

- 完整链路已验证：NPC 入口 → 独立场景 → 逐步取证 → 刷新恢复 → 选择结论 → 回执 → 回街区每日锁 → Trading 情报显示。调查不改现金，也不强制下单。
- 首轮 `NO_CATALYST` 案例暴露了证据文字重复：不同材料都显示同一条泛化发现。已修复 `ChenDossierScreen.ts` 的表现映射，让每类材料按来源和现有 finding 显示不同内容；未改 Core 判定、可信度规则、存档结构或精力成本。第 3 天 `INFLATED_ORDER` 浏览器回归确认三条来源文案各自不同，且回执保留完整分项。
- 本轮 Core 将证据结果拆成来源表：夸大订单案例里备案、供应商排期、发票回款分别返回负面、局部支持、负面结果；可信度与建议按材料数量和冲突计算。至少两项同向材料才给买入/回避方向；单项证据建议观望。没有增加存档字段或版本迁移。
- 第一次浏览器查看新“无催化”回执时发现“你选择暂缓入场”重复出现；已修复并通过本轮浏览器复验，没有重复。
- 当前案例仍在副本开始时按股票剧本阶段固定；本轮已在浏览器确认 `INFLATED_ORDER` 的混合证据回执与可信度提示。真实合同与跨来源相符回执、快速浏览、窄屏仍未完整体验；不能把本轮单个案例当作完整动态侦查系统。
- 已验 `NO_CATALYST` 的保守结论与 `INFLATED_ORDER` 的回避结论；没有验 `REAL_CONTRACT`、快速浏览路线、主动退出、窄屏、崩溃或长期情报效果。不能据此认为三类案例已完整验收。
- 不将单次浏览器操作视为正式数值平衡；18 点精力和调查每日一次是现有原型规则，不在本轮重定价。
